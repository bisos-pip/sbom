** -sbom.pcs Convention
A =-sbom.pcs= file is a Python script (bisos CS-Unit) that:
1. Imports =pkgsSeed= and calls =pkgsSeed.setup(...)= to declare what to install
2. Optionally defines a =readme= CS-command (human-readable description)
3. Optionally defines =examples_csu()= for the example menu
4. Is invoked as =<name>-sbom.pcs -i sbom_fullUpdate= to install everything

** Package Type Shorthands (used in -sbom.pcs files)
| Alias  | Full form           | Usage                                 |
|--------+---------------------+---------------------------------------|
| =ap=   | =pkgsSeed.aptPkg=   | Debian apt package                    |
| =pp=   | =pkgsSeed.pipPkg=   | Python pip package                    |
| =npm=  | =pkgsSeed.npmPkg=   | npm package (global or local)         |
| =sbom= | =pkgsSeed.sbomSpec= | Inter-sbom dependency (run first)     |

* Data Model: pkgsSeed.py

** Classes
| Class          | Key Attributes                   | Notes                                   |
|----------------+----------------------------------+-----------------------------------------|
| =AptPkg=       | =name=, =func=, =osVers=         | func() called instead of apt if set     |
| =PipPkg=       | =name=, =func=, =ver=            | ver pins exact version                  |
| =NpmPkg=       | =name=, =func=, =ver=, =scope=   | scope="global" (default) or "local"     |
| =SbomSpec=     | =name=                           | path to another -sbom.pcs file          |
| =PkgsSeedInfo= | aptPkgsList, pipPkgsList, npmPkgsList, sbomsList, virtenv | Singleton |

** Factory Functions
- =aptPkg(pkgName, func=None, osVers=None)= → AptPkg
- =pipPkg(pkgName, func=None, ver=None)= → PipPkg
- =npmPkg(pkgName, func=None, ver=None, scope="global")= → NpmPkg
- =sbomSpec(sbomName)= → SbomSpec
- =setup(aptPkgsList, pipPkgsList, pipxPkgsList, npmPkgsList, sbomsList, examplesHook, virtenv)= — populates singleton

** PkgsSeedInfo Singleton
: pkgsSeedInfo = PkgsSeedInfo()   # module-level singleton

Key methods:
- =aptPkgsNames()=, =namedAptPkg(name)=
- =pipPkgsNames()=, =namedPipPkg(name)=
- =npmPkgsNames()=, =namedNpmPkg(name)=
- =sbomSpecsNames()=, =namedSbomSpec(name)=
- =pipCmnd()= → ="pip"= or ="{virtenv}/bin/pip"=
- =binPath(execName)= → bare name or fully-qualified virtenv path

** virtenv support
Setting =pkgsSeedInfo.virtenv = "/bisos/venv/py3/asc"= (or via =setup(virtenv=...)=)
causes =pipCmnd()= and =binPath("pip")= to return =/bisos/venv/py3/asc/bin/pip=.
All pip installs and checks use this path. When =virtenv=None= (default), PATH is used.

** sbom_fullUpdate execution order
1. =sbomSpecs_fullUpdate= — processes all =sbomsList= entries (inter-sbom deps)
2. =aptPkgs_update("all")=
3. =pipPkgs_update("all")=
4. =pipxPkgs_update("all")=
5. =npmPkgs_update("all")=

** NpmPkg install logic (npmPkgs_update)
- If =func= is set on the NpmPkg, call =func()= directly (custom installer)
- Else: =npm install [--global] <pkg>[@ver]= where =--global= is added when =scope == "global"=
- Skips install if =npmPkg_isInstalled= returns True (idempotent)

* Design Decisions & Lessons Learned

** f-string vs plain string for bash function bodies
When a -sbom.pcs function embeds a bash script string that contains ={...}=
(e.g. =${NVM_VERSION}=, =${HOME}=), do NOT use =f"..."= prefix.
Use a plain string literal ="""..."""= to avoid Python SyntaxError
(=f-string expression part cannot include '#'=, etc).

** nvm is per-user, not system-wide
- =npm root -g= on the development system returns =~/.nvm/versions/node/v22.21.1/lib/node_modules=
  — this means nvm is active and system Node is actually nvm-managed
- Global npm packages are installed per-nvm-version
- Installing reactPlus packages with nvm active means they land in the nvm version's tree
- After =nvm use <new-version>=, run =sbom_fullUpdate= again to re-install globals

** apt-installed npm (system) vs nvm npm
| Context                   | Which npm      | Globals land in                                          |
|---------------------------+----------------+----------------------------------------------------------|
| nvm active (normal user)  | nvm's npm      | =~/.nvm/versions/node/<ver>/lib/node_modules/=           |
| nvm NOT active / root     | system apt npm | =/usr/lib/node_modules/=                                 |

** Claude Desktop Linux
The official Anthropic Claude Desktop app does not provide a native Linux .deb.
The community package at =pkg.claude-desktop-debian.dev= provides an unofficial port.

** npm: a package's own install decides; "absent" is not an error (2026-11-25)

From bxGenesis/base AI-WorkPlan 3.2.4 (the 261124-1 VM run): =revealJs-sbom.pcs= (bisos.lcnt) installs
reveal.js with its own =func= (system =/usr/bin/npm=, =/usr/local=), but =npmPkgs_update= first ran the
generic =npmPkg_isInstalled= (=npm list --global= under the user's nvm, another prefix): exit 1, left as
an error in the shared outcome, so =sbom_fullUpdate= failed and skipped its nested sboms. Now, in
=sbom_csu.py=: a package with a =func= goes to it directly, and =npmPkg_isInstalled= runs
=npm list ... || true= (its stdout decides). Untested; reaches the VM with the next bisos.sbom release.

** Inter-sbom dependencies (sbomsList / sbomSpec)
Declaring =sbomsList= in a -sbom.pcs causes =sbom_fullUpdate= to call
=sbomSpecs_fullUpdate= first, which runs each listed sbom's =sbom_fullUpdate=
in order. This is the standard way to express prerequisites.
